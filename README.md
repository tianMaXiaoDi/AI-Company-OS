# AI Company OS

> 365 天把个人能力沉淀为一套由你管理、由 AI 协作执行、能够持续交付价值的「一人公司操作系统」。

## 北极星目标（第 365 天）

- 一个公开、持续更新的 GitHub 项目与个人网站。
- 一套可复用的 Agent / Workflow 基础设施：开发、客服、增长、内容、数据、求职等能力按需组合。
- 至少一个已上线、真实用户可用并有收入或明确验证数据的 AI 产品。
- 一份能支撑海外远程/AI 岗位竞争力的作品集与公开工作记录。
- 一套每周复盘、每月迭代、可追踪决策与资产的经营机制。

这不是「连续 365 天学工具」项目。每个学习任务都必须服务于一个可复用能力、一个可演示交付物，或一个经过验证的商业假设。

## 先从这里开始

1. 阅读 [愿景与边界](docs/01-vision.md) 与 [路线图](docs/02-roadmap.md)。
2. 把今天的唯一关键任务写入 `planning/daily/YYYY-MM-DD.md`（从模板复制）。
3. 从 [第 1 个月每日计划](docs/06-daily-plan-month-01.md) 选择当天任务。
4. 每晚更新任务状态、日报和证据链接；每周按 [周计划](docs/07-weekly-plan.md) 做复盘。

## 项目结构

```text
ai-company-os/
├── README.md
├── docs/                 # 战略、路线图、运行手册
├── planning/             # 日、周、月计划与复盘（私有信息可不公开）
├── agents/               # 每个 Agent 的职责、输入输出、评估与版本记录
├── workflows/            # 多 Agent 工作流及其运行说明
├── knowledge/            # 经提炼的知识，不存原始杂物
├── products/             # 可上线产品的需求、实验、指标
├── tools/                # 脚本、集成、环境说明
├── demos/                # 可复现实验与演示
├── metrics/              # 指标定义和月度快照
└── templates/            # 日报、周报、Agent、实验等模板
```

## 工作节奏

| 频率 | 固定产出 | 判断标准 |
| --- | --- | --- |
| 每天 | 1 个 MIT（最重要任务）、日报、可验证证据 | 是否推进本周交付 |
| 每周 | 1 个可演示增量、复盘、下周承诺 | 是否让用户/作品集/系统变得更好 |
| 每月 | 1 个里程碑、指标快照、方向选择 | 是否缩小到可持续的产品与能力 |
| 每季度 | 战略回顾与路线图重排 | 是否继续投入、加速或停止 |

## 核心原则

1. **先工作流，后多 Agent。** 能用确定性代码、API 或规则解决的，不强行 Agent 化。
2. **小而可组合。** 一个 Agent 只对一个明确职责负责；输入、输出、工具、边界、评估必须写清。
3. **证据优先。** 「完成」必须附 PR、截图、Demo、运行记录、用户反馈或指标。
4. **真实问题优先。** 每月至少一次与真实用户、真实工作或真实业务流程接触。
5. **每周可交付。** 不把「研究」当作完成；研究必须转化为决策、原型或文档。
6. **隐私与权限最小化。** 不在仓库提交密钥、客户数据、身份证明或私密对话。
