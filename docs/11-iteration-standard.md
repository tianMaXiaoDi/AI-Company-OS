# 后续迭代规范

## Agent / Workflow 变更流程

1. **问题定义：** 记录用户场景、当前失败和预期改善。
2. **最小变更：** 每次只优先改变一个维度：Prompt、工具、数据、编排或模型。
3. **离线评估：** 在固定案例集上比较基线与新版本；记录成功率、质量、成本、时延和失败类型。
4. **人工审阅：** 对高风险输出、边界案例和回归案例抽检。
5. **小范围上线：** 保留回滚方式、日志、反馈入口与审批点。
6. **复盘沉淀：** 写入 changelog、案例集和知识库；若无改善则回滚或归档。

## 版本约定

- `v0.x`：探索，接口和行为可快速变化。
- `v1.x`：已可重复演示，拥有基础评估与使用说明。
- `v2.x`：真实使用，具备监控、成本记录、权限与变更控制。

## 文档与决策规则

- 架构/产品/工具方向的不可逆决定：新增 `planning/decisions/ADR-xxx-*.md`。
- 任何 Prompt、模型或工具变更必须写入 Agent `changelog.md`，并关联评估结果。
- 任何真实用户反馈进入 `products/<product>/research/`，需去标识化。
- 每个季度清理：归档不再投入的实验，保留停止原因，避免重复试错。

## 发布门槛

对外 Demo 至少具备：README、运行步骤、示例数据、已知限制、反馈入口。涉及账户、订单、退款、邮件或生产系统时，必须默认只读、最小权限、可审计，并在执行前人工确认。
