# 里程碑与验收标准

| ID | 时间 | 里程碑 | 验收标准 |
| --- | --- | --- | --- |
| M0 | Day 7 | 项目启动 | 仓库、愿景、组织图、首个 Agent 与 RAG Demo 可运行 |
| M1 | Day 30 | 基础设施完成 | 任务、日报、周报、月报机制已使用 4 周；自动化 Demo 可复现 |
| M2 | Day 60 | 工程 Agent v1 | 至少 3 个 Agent 各有职责卡、10 条测试案例、失败边界说明 |
| M3 | Day 90 | 工程工作流 v1 | 一个从输入到报告的可演示编排流程，保留成功率与人工修正数据 |
| M4 | Day 120 | 客服 MVP | 支持知识问答、订单查询、人工升级；不直接执行高风险动作 |
| M5 | Day 150 | 客服试点包 | 退款决策建议、规则审计、部署说明与演示录屏 |
| M6 | Day 210 | 产品信号 | 目标用户、核心痛点、原型、访谈记录和继续/停止决策 |
| M7 | Day 270 | 可运营产品 | 上线、埋点、监控、反馈闭环、首批真实使用或收入信号 |
| M8 | Day 330 | 可复制系统 | 至少 3 个内部流程由 OS 支撑，作品集与英文材料完备 |
| M9 | Day 365 | 年度经营复盘 | 一条明确主线、年度指标、资产清单、下一年度路线图 |

**验收规则：** 仅完成代码不算完成。每个里程碑都要在 `planning/monthly/` 留下链接到 Demo、指标、反馈和复盘的证据。
