# 运行手册

## 每日 2–4 小时模板

| 时段 | 内容 | 产出 |
| --- | --- | --- |
| 20 分钟 | 阅读/回顾上下文 | 一个可执行决策或笔记 |
| 90 分钟 | 当天 MIT 深度构建 | 最小可验证增量 |
| 30–60 分钟 | 测试、评估、文档 | 证据链接与失败记录 |
| 15 分钟 | 日报、任务更新、明日准备 | 当日复盘与明日草案 |

建议早晨 20–30 分钟用于行业阅读；如果晚间只能完成一件事，优先完成 MIT，而非补看教程。

## Definition of Done

任务要同时满足：

- 明确说明变更了什么及为何变更。
- 有运行/评估/截图/链接等证据。
- 更新相应文档、任务状态和下一步。
- 涉及 Agent 时，至少记录一个失败案例或边界。
- 涉及外部影响时，已完成必要的人工审核。

## 知识沉淀流程

`原始文章/对话 → 关键判断 → 可复用模式 → 项目中的应用 → 评估结果`。

只有最后三项进入 `knowledge/`；原文用链接与简短摘要引用。每条知识要标注来源、日期、可信度和最后验证时间。
