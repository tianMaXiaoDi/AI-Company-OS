# 任务管理方式

使用 GitHub Projects、Notion、Linear 或一个 Markdown 看板均可；工具不是重点，以下字段和规则不可缺失。

## 看板列

`Inbox → Validated → This Month → This Week → In Progress → Review/Eval → Done / Archived`

## 每张任务卡必填字段

- 标题：动词开头，例如「验证退款建议工作流的正确率」。
- 类型：`product` / `agent` / `workflow` / `research` / `growth` / `ops`。
- 关联目标：季度目标、月度关键结果或里程碑 ID。
- 成功标准与证据形式。
- 优先级：P0（阻塞本周交付）、P1（重要）、P2（有价值）、P3（想法）。
- 预估：S（≤2h）、M（半天）、L（1–2 天）；超过 L 必须拆分。
- 风险/依赖、负责人（默认你）和截止周。

## WIP 限制与优先级

- `In Progress` 同时最多 1 张 P0 + 1 张 P1。
- 每周最多 5 张执行卡；没有完成旧卡，不新开同等优先级工作。
- 优先级按 **影响 × 证据强度 ÷ 成本** 判断。不能解释影响与证据的任务，先放 Backlog。
- `Done` 一周后才可归档；复盘时从 Done 中提炼资产和后续任务。
